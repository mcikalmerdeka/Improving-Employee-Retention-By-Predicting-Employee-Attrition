# Improving Employee Retention By Predicting Employee Attrition

A reproducible attrition study and Streamlit app for an Indonesian technology
company. The notebook audits 287 employee records, builds a leakage-safe binary
classifier, evaluates it honestly, and exports one model artifact. The app
loads that artifact to score one employee or a whole CSV and explain the score.

> **Honest framing:** the available features separate leavers from stayers only
> weakly. The model is a **ranking and screening aid**, not a high-confidence
> individual predictor. The notebook reports the real held-out metrics and a
> cumulative-gains analysis instead of claiming an accuracy figure.

## What is in the project

```

```

## Setup

Requires Python 3.14 and [uv](https://docs.astral.sh/uv/).

```powershell
uv sync
```

## Run the notebook

Open `notebook.ipynb` in VS Code with the project `.venv` kernel, or execute it
headlessly:

```powershell
uv run jupyter nbconvert --to notebook --execute --inplace notebook.ipynb --ExecutePreprocessor.timeout=1800
```

The notebook writes `models/attrition_model.joblib` as its final step.

## Run the app

```powershell
uv run streamlit run main.py
```

The app refuses to start without the artifact and tells you to run the notebook
first.

## Run the tests

```powershell
uv run pytest -q
```

The AppTest cases skip automatically when the artifact is missing.

## Model and data notes

- **Target:** `StatusKerja` — 1 = resigned (`TanggalResign` present), 0 = still
  working. There are 89 leavers out of 287 employees (31.0%).
- **Excluded:** `Username`, `EnterpriseID`, `NomorHP`, `Email` (PII);
  `PernahBekerja` (invalid constant); `IkutProgramLOP` (89.9% missing);
  `AlasanResign` (known only after resignation); `TanggalResign` (defines the
  target); `TanggalPenilaianKaryawan` (after resignation for 64 of 89 leavers).
- **Used:** profile, employment, performance, engagement, satisfaction,
  project, lateness, absence, age at hire, and hiring year/month features.
- **No PII** is stored in the artifact or shown in the app. Example profiles use
  a synthetic 2005 hire anchor and a derived birth date that preserves age at
  hire; no real birth dates are stored.

## Limitations

- 287 rows and 87 test rows make the estimates noisy.
- The signal is weak; use the probability and risk tier for prioritisation, not
  as an automatic decision.
- The dataset is a snapshot, not a time series. A survival or time-to-event
  model would be the next step if dated snapshots become available.
- Correlation is not causation. Validate drivers with HR before acting on them.
